# Automatic execution workflow

## Scope and prerequisites

For "set this up", "fix the bridge", "finish setup" or a requested bridge call, Codex executes the necessary setup. A status report is not completion. An audit-only/verification-only request remains read-only; distinguish that from a request to remedy the reported failures. Editing these instructions is not permission to change the current host's audio.

Retain the dedicated alternate-account prerequisite. Reuse an explicit confirmation made by the user in the current task that the dedicated account is currently signed in; do not repeatedly ask within that task. A stored flag, old acceptance or the assistant's own assumption is insufficient. Each new wizard session still requires its checkbox. Do not click that checkbox or pass the helper assertion without the user's actual confirmation.

Resolve the installed plugin root from this skill's location: the parent of the skills directory contains scripts and config. Use the installed bundle's actual absolute path, not a source-machine path or guessed cache version. Read the helper parameter definitions before invoking them. Examples below are relative to that resolved plugin root.

## Execute in dependency order

Use `scripts/Invoke-AutomaticSetup.ps1 -DedicatedAccountConfirmed -InstallMissing -VoiceApplication '<observed actual Voice app>'` as the default setup runner after checking current dedicated-account confirmation and the host/vendor suitability of the documented cables. Omit `-InstallMissing` when dependencies are already present or installation is outside scope. Never invent the Voice application name. The runner reuses detected apps/cables, invokes missing dependency helpers, avoids relaunching pending drivers, selects unambiguous enabled send/return endpoints, saves per-machine preferences and produces `routing-plan.json` plus `Routing-progress.json`. Existing explicit device preferences take precedence; resolve stale or ambiguous preferences from fresh device evidence rather than silently replacing them.

The runner's `ReadyForAgentApplication` means the selected route is ready for Codex to APPLY, not that audio is routed. Execute its actions in order through available supported controls and read back each actual setting. Do not deliver the plan as a checklist. Preserve concrete settings-readback evidence in the per-machine restore/acceptance records; do not flip `applied` to true based on script exit, device enumeration or a planned click. If interrupted by UAC or restart, inspect saved progress and fresh endpoints, finish the specific handoff, then rerun the runner and continue app actions. A historical `RestartRequired` with still-missing endpoints needs installer/process and reboot evidence inspected before retrying; it does not authorize an automatic reboot.

The detailed sequence below also provides recovery steps when an individual runner stage fails. Continue independent supported stages rather than abandoning all setup because one stage needs attention.

1. Run `scripts/Bootstrap.ps1 -Mode Audit` yourself. Inspect enabled endpoint pairs, actual app paths/versions, config and pending installer progress. Check host native/screenshot capability and actual Voice availability independently. Do not change a live unrelated call or stream.
2. After dedicated-account confirmation, run `scripts/Bootstrap.ps1 -Mode Prepare -DedicatedAccountConfirmed` yourself to create missing local templates while preserving existing settings. Capture original app/audio settings before applying any routing changes.
3. If OBS or Discord is missing and installation is within scope, run `scripts/Bootstrap.ps1 -Mode InstallApps -DedicatedAccountConfirmed` yourself. Reuse installed software. If WinGet is unavailable, inspect the documented official installation path and available tools; perform authorized download/preparation and supported installer launch yourself. Hand off only vendor agreements or unavailable controls. Do not install unrelated runtimes to conceal a host control limitation.
4. For a missing outbound pair, invoke `scripts/InstallDriver.ps1 -Driver VBCable -DedicatedAccountConfirmed` yourself. The helper downloads, verifies the publisher, and opens the vendor installer visibly with ordinary UAC. The user approves secure-desktop UAC. Codex then uses supported UI to finish available non-protected installer steps, respecting license prompts and the user's restart choice. Do not merely tell the user to find/download/run the installer. Track pending state; do not launch duplicates after uncertain outcomes.
5. For a missing return pair, reuse a compatible independent cable when available. Otherwise perform the same supported helper flow for `-Driver HiFiCable` when appropriate for the host/vendor terms. If compatibility or license choice actually requires a user decision, prepare the concrete available option and state that specific dependency; do not buy an alternative or claim an unqualified legacy driver is compatible. Never use the outbound pair for the return route.
6. Re-run read-only detection after installation and any user-approved restart. Verify both enabled endpoints per cable; installer exit zero is not proof. If a restart is required, save progress and give the single restart handoff; resume detection when the user returns. No recurring automation or automatic reboot is created.
7. Through supported native or screenshot-based Computer Use, create/select the isolated OBS profile/collection, select ONLY actual Voice audio capture, set monitoring to the outbound playback endpoint, unmute the source, set Discord microphone to the outbound recording endpoint, set Discord output to return playback, and select return recording as Voice input. Use current device names and observed UI. Save the corresponding per-machine preferences yourself after selections are established. Writing JSON alone does not apply these app settings. Keep caller return and unrelated audio out of the outbound capture.
8. Start/reuse Voice yourself through a supported tool or observed UI control. Verify listening/speaking and actual playback. If activation really is unavailable, finish other available work before requesting only that manual action. Do not confuse Dictate with live Voice or silently switch to paid API speech.
9. Perform the local intelligibility/echo checks, stop Discord mic test, and proceed with the explicitly requested call only after prerequisites pass. A setup-only request never authorizes dialing. Verify remote hearing and fresh inbound conversation separately. Handle an explicit hang-up through the actual Discord and associated Voice endpoints.

## Narrow handoffs and continuation

For `0x80004002` native capture failures, follow host-preflight.md: use an independently available supported screenshot-and-input Computer Use interface when it works. If none is available, native routing/recipient verification/calling are blocked. Shell preparation, official driver downloads, scoped installer launch and status inspection may still be available; complete those before ending the turn. Do not assume a screenshot can be taken or that a browser-only tool operates native apps.

A valid partial report identifies: actions Codex actually completed; the exact remaining step; the tool failure or user-only boundary; and what Codex will resume after the handoff. For example: "I downloaded and verified the cable installer and requested its UAC launch. Approve that Windows prompt; I will then check for both endpoints and continue routing." Use this wording only if those actions really happened. If input controls are unavailable after UAC, ask the user to complete only the visible installer steps rather than falsely promising automatic completion.

An invalid setup response says only "verification partial; configure two cables using the wizard, then start Voice manually" despite available helper execution. Do not stop at that response. No manual handoff is needed for routine authorized helper commands, current-scope device enumeration, or configuration-file preparation.

When every remaining action depends on a missing capability or explicit user action, report the bounded blocker truthfully. Instructions cannot create native-control or Voice capabilities that the host does not expose.
